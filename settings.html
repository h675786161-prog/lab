SETTINGS

第一次用？这里一个都不用改。

默认设置就是给正常使用准备的。你有明确目的以后，再来找对应那一块。

✓ 推荐：先保持默认

能正常打开、后台会更新，就继续聊天。别因为看到四大栏设置，就觉得自己必须先考个驾驶证。

我想改的是： 外观 / 圆球 正文里出现太多或太少 接口 / 模型 备份 / 排错 / 重置
01 · 常用

这一页每个开关，到底动了什么？

常用页不只是外观。下面把你真实能点到的 7 个设置全部拆开。

完整真实界面点右边说明，左图会带你跳到对应位置原尺寸 ↗
怎么读这张图

先看编号，不用从头背。你想改哪个，就点右边那一项，左图会自动滚到对应位置。

1
只改外观

界面明暗

它管什么：决定世界背面的界面用自动、日间还是夜间主题。

自动跟着世界时间判断昼夜。
日间固定亮色界面。
夜间固定暗色界面。

改了会怎样：只影响你看到的界面，不改变世界状态、模型或推演结果。

什么时候动：单纯觉得亮或暗不舒服时改。

2
只改阅读密度

界面字号

它管什么：控制面板里文字和控件的阅读尺寸。

紧凑同屏信息更多。
标准默认阅读密度。
大字手机、小屏或远距离阅读更舒服。

改了会怎样：不会改变生成内容，只改变界面排版。

什么时候动：字太挤、太小，或者你想一屏看更多内容时改。

3
入口显示

显示悬浮球

它管什么：控制聊天界面上那个打开世界背面的悬浮入口是否显示。

改了会怎样：关掉以后插件照常运行，只是悬浮入口消失；之后仍可从 SillyTavern 的扩展设置重新打开。

什么时候动：悬浮球挡住主题按钮或聊天内容时。

4
入口收纳

悬浮球贴边收纳

它管什么：让悬浮球自动吸到最近的屏幕边，只露出一部分。

改了会怎样：入口仍然可以点击，不会关闭插件。

什么时候动：觉得悬浮球碍眼，但又不想彻底隐藏时。

5
后台总开关

启用世界引擎

重要

它管什么：决定镜头外的世界还要不要继续推演。

改了会怎样：关掉以后不会继续产生新的后台发展，但已经发生、已经记录的世界状态不会被删除。

什么时候动：你想临时冻结后台世界，或者正在排查推演问题时。

6
自动推演

自动运行

它管什么：决定世界背面是否按设定条件自动醒来进行推演。

改了会怎样：关掉以后不是“世界引擎失效”，而是改成等你手动触发。

什么时候动：你希望完全自己控制什么时候推演，或暂时减少自动请求时。

7
人物社交自动化

通讯自主活动

它管什么：控制人物是否会自己发消息、发好友申请、删好友或发朋友圈。

改了会怎样：关闭后，已有通讯录和你主动进行的手动聊天仍然保留。

什么时候动：你只想自己主动聊天，不希望 NPC 在通讯系统里自行活动时。

🌸

第一次用：主题、字号和悬浮球按喜好调；世界引擎、自动运行、通讯自主活动没有明确需求就先别动。

02 · 正文注入

“后台有”与“正文看见”是两回事。

这一页的 12 个设置全部围绕一件事：后台已经知道的东西，这一轮要不要、什么时候、以多大频率递给正文。

完整真实界面点右边说明，左图会带你跳到对应位置原尺寸 ↗
怎么读这张图

最容易误会的是总开关。这里任何“关闭”都不等于删除对应后台数据。

1
总闸门

正文注入总开关

不等于停机

它管什么：决定后台信息是否递给当前正文模型参考。

改了会怎样：关掉只会让后台“记着但先不说”，人物、暗流、记忆和舆情仍可继续运行。

什么时候动：想临时测试“完全不带后台信息”的正文表现时。

2
来自「此刻」

世界时间

它管什么：决定要不要把当前世界时间递给正文，以及递到多精确。

完整日期、时段和具体时间都会给正文。
最小锚点只提供维持时间连续性所需的信息。
关闭正文不接收世界时间。

改了会怎样：只影响正文这一轮看到的时间信息，世界背面的时钟本身不会因此消失。

什么时候动：模型总把时间写得太死，或反过来经常把昼夜、日期写乱时。

3
来自「此刻」

世界背景

它管什么：把世界长期成立的背景与地基信息递给正文。

改了会怎样：关掉以后背景仍保存在后台，只是不主动进入正文上下文。

什么时候动：背景信息太长、抢占上下文，或当前剧情暂时完全用不到时。

4
来自「人物」

当前状态

它管什么：把人物现在的位置、行动等当前状态递给正文。

改了会怎样：关掉不会停止人物在后台生活，只是不把这些状态主动告诉正文。

什么时候动：正文老被镜头外人物抢戏，或你想让某段剧情更局部时。

5
来自「暗流」

进行中事件与世界环境

它管什么：把仍在发展的事件、环境变化和镜头外进程递给正文。

改了会怎样：暗流仍会继续发展，只是正文暂时看不到。

什么时候动：世界变化出现得过于频繁，压住当前场景时。

6
来自「回声」

已结算后果

它管什么：把已经发生并结算完成的后果带给正文，用来防止结果被悄悄改写。

改了会怎样：关闭注入不会删除这些后果。

什么时候动：通常保持开启；只有你明确不想让正文携带这些结果时再关。

7
来自「此刻」

世界事实

它管什么：把已经成立的事实作为对账依据递给正文。

改了会怎样：有助于避免“烧掉的信又出现”“已经停电却突然有电”一类事实冲突。

什么时候动：一般不需要动；如果上下文特别拥挤再考虑暂时减少。

8
来自「记忆」

长期记忆

它管什么：把整理后的重要事实、关系、承诺与未收尾线索递给正文。

改了会怎样：关闭后记忆系统仍可以继续整理，只是不把记忆主动塞进正文。

什么时候动：长期记忆开始重复、抢戏，或你正在测试纯当前上下文时。

9
来自「舆情」

新闻与论坛

它管什么：把世界里的新闻、论坛和公共风声递给正文。

改了会怎样：舆情本身仍可变化；这里只控制它离当前镜头有多近。

什么时候动：公共信息太容易闯进私密场景时。

10
来自「通讯」

最近聊天

默认隔离

它管什么：把尚未结算的通讯记录作为正文参考。

改了会怎样：即使开启，也只是告诉正文“谁说过什么”；聊天里的约定不会自动被当成已经发生的事实。

什么时候动：你希望线下正文能接住之前的私聊内容时。

11
显露策略

正文显露度

它管什么：控制已经允许注入的信息出现得有多勤快。

克制少往镜头边递变化。
均衡重要的递，不重要的先留后台。
活跃更积极地让后台变化靠近正文。

改了会怎样：它改变“出现频率”，不是改变后台是否存在。

什么时候动：觉得后台信息太安静或太抢戏时。

12
显露策略

显露时机

它管什么：控制后台变化适合在什么场景进入正文。

严格只在转场或空档显露。
智能关键场景先延后，合适时再出现。
开放允许更频繁的简短自然变化。

改了会怎样：越开放越容易在连续场景里看到世界变化。

什么时候动：后台信息出现的位置不合时宜时，先调这个而不是删数据。

☾

出现“后台抢戏”时先调显露度和显露时机；出现“模型老忘事实”时再检查对应注入项有没有被关。

03 · 连接与模型

接口页不用怕，按“走哪条路”理解就行。

这页看着最技术，但真正需要理解的是 6 块。独立接口那块我把每个输入框和按钮都拆开写了。

完整真实界面点右边说明，左图会带你跳到对应位置原尺寸 ↗
怎么读这张图

能正常跑就先看第 1、2 项，别急着填 Key。只有你明确要分接口、分模型时，才往下面走。

1
先看，不用改

当前连接状态

它管什么：这里告诉你世界推演现在实际走哪条连接、用什么模型、什么方式，以及当前是否正常。

模型当前实际使用的模型。
方式例如独立上下文推演。
状态等待正文、运行中或错误。

改了会怎样：这是状态牌，不是一个需要填写的设置。

什么时候动：第一眼判断“到底有没有接上”时先看这里。

2
选择走哪条路

世界推演连接

它管什么：决定世界推演使用酒馆当前连接、酒馆已保存方案，还是世界背面的独立接口。

跟随当前酒馆主聊天换模型时，世界背面也跟着换。
酒馆已存方案固定读取 SillyTavern 保存的连接方案，只记方案 ID，不复制 Key。
独立接口世界背面自己使用单独的 URL、Key 和模型。

改了会怎样：只改变推演请求走哪条连接，不会改主聊天的模型。

什么时候动：正常能用就保持当前方案；确实需要分开模型或接口时再改。

3
URL / Key / 模型

独立接口配置

有自己的接口才用

它管什么：给世界背面单独配置一条 OpenAI 兼容连接。

接口地址填到版本层，例如 https://example.com/v1；后面的 /chat/completions 由插件补。
API Key保存在本机扩展设置，不写进导出的世界状态；已有 Key 时留空表示继续使用。
模型名称可以手填，也可以先“拉取模型列表”再选择。
连接方式经酒馆服务器转发是推荐方式；浏览器直连需要目标接口允许浏览器访问。
方案名称可选。起名后方便保存成可复用方案。
保存默认独立接口并生效把当前表单设为默认独立连接。
保存为方案 / 测试连接 / 拉取模型列表分别用于复用、连通性检查和获取模型名。

改了会怎样：填写错误最常见的表现是测试失败或后台请求报错，不会直接改坏世界数据。

什么时候动：你明确要让世界背面和主聊天分开走接口时。

4
可选能力

朋友圈生图接口

它管什么：给通讯里的朋友圈配图单独设置生图接口。

允许朋友圈生成配图开关关闭时不会自动请求图片。
生图 API 地址使用 OpenAI 兼容的 /images/generations，地址填到 /v1；当前为浏览器直连，需要 CORS。
生图 API Key只保存在本机扩展设置。
生图模型例如 gpt-image-1 或你的接口支持的模型。
图片尺寸选择接口支持的尺寸。
生成测试图（会计费）真的会请求一次图片，用来验证接口。

改了会怎样：关闭开关不会删除已经生成过的朋友圈图片。

什么时候动：只有你想让朋友圈自动配图时才需要配置。

5
复用连接

世界背面自存方案

它管什么：把常用独立接口保存成方案，之后不用重复填写 URL 和 Key。

编辑修改方案。
测试验证方案是否可用。
模型为方案拉取可用模型。
复制复制一份方案再改。
删除删除该保存方案。

改了会怎样：这里只管理世界背面自己保存的连接方案。

什么时候动：你有两条以上常用接口，或者经常切模型时。

6
高级连接用法

模块 API 分流

它管什么：让不同后台任务分别走不同模型或连接。

世界推演镜头外世界发展。
人物即时观测临时查看人物状态。
长期记忆 / 历史整理记忆建档与整理。
世界舆情新闻与论坛生成。

改了会怎样：没有单独指定的模块继续跟随世界背面默认连接。

什么时候动：只有你已经确认默认连接稳定，并且确实想按任务拆模型时再用。

🧶

排错顺序：先看当前连接状态 → 再测试独立接口 → 最后检查模块分流。不要同时改三层，不然很难知道是哪一层断了。

04 · 高级维护

这里不是“高级效果”，而是修理箱。

六个折叠组全部展开给你看。真正危险的操作我会明确标红，其他按钮分别说明会碰什么、不会碰什么。

完整真实界面点右边说明，左图会带你跳到对应位置原尺寸 ↗
怎么读这张图

高级维护最重要的不是“会不会用”，而是分清备份、清缓存、纠错、重置、恢复各自会动哪一层。

1
Token 与等待时间

生成限制

它管什么：给后台请求设全局输出长度和最长等待时间，还可以按模块单独覆盖。

全局 Token 上限自动、4K、8K、12K 或自定义；0 表示让插件自动决定。
全局最长等待自动、60s、120s、180s 或自定义；只计算模型真正生成的时间，不把排队、限流冷却算进去。
按模块单独设置世界推演、人物观测、历史/记忆、舆情可以各自覆盖；填 0 就继承全局。
自动等待参考世界推演 180s、人物观测 120s、历史/记忆 300s、舆情/闲逛 150s。

改了会怎样：设得太小容易截断或超时；设得很大也不会突破服务端自己的限制。

什么时候动：频繁出现输出被截断或模型生成超时时再来调。

2
搬家前先装箱

数据备份

建议先备份

它管什么：导出当前世界状态，或把之前导出的世界状态重新导入。

导出当前世界保存当前聊天对应的后台世界。
导入世界状态把备份状态恢复进来。

改了会怎样：适合迁移、测试和大调整前留保险。

什么时候动：准备重置、导入、大改设置或做高风险测试之前。

3
三个按钮完全不是一回事

数据维护

重置有风险

它管什么：这里同时放了轻量清理、纠错和真正清空数据三个动作。

清理当前聊天缓存只扫临时缓存，不碰人物、记忆和世界状态。
让玲七检查世界状态拿正文和明确事实重新对账；后台错了就修后台，不改已经发生的正文。
重置当前聊天数据把当前聊天的后台世界清空，不碰正文和 API / 模型配置，而且不可撤回。

改了会怎样：前两个用于排错，第三个相当于给这个聊天的世界背面重新开档。

什么时候动：“一键重置”前一定先导出备份；不要把它当刷新按钮。

4
只让叙事进入后台

正文过滤

它管什么：避免变量块、脚本块、状态栏等非叙事内容被当成剧情事实。

启用标签过滤控制成对标签过滤；HTML 注释即使关掉这个开关也会先被排除。
只读取某个正文标签可选。有这个标签时只读标签内部；没有该标签的消息仍保留原文。
额外正则排除一行一条，适合滤掉变量块或预设附加内容。
规则 1…N手动填写开头标签和结尾标签；任一边可留空。
自动提取候选可扫描最新正文或最近 5 条，只列出可疑标签，不会擅自添加。
添加选中候选 / 添加规则确认后才真正加入过滤规则。

改了会怎样：规则写得过宽可能把真正剧情一起滤掉，所以这栏适合“有明确脏内容”再配置。

什么时候动：后台开始把变量、脚本、状态栏当成故事内容时。

5
世界状态后悔药

安全恢复

它管什么：查看当前聊天最近的恢复点，手动保存新的恢复点，或恢复到最近保存。

立即保存恢复点给现在的后台状态留一份保险。
恢复最近保存回到最近恢复点；恢复前还会先替当前状态再留一份保险。

改了会怎样：恢复点按聊天分别保存；升级旧数据、导入状态时也会自动留保险。

什么时候动：后台状态明显跑偏、导入后不对，或做高风险操作之前。

6
求助时用

故障诊断

它管什么：整理版本、设备、接口模式和错误状态等排错信息。

把诊断叼出来复制可以直接发给维护者的诊断信息。
看看提示样式预览插件提示长什么样。

改了会怎样：诊断不会把 API Key、接口地址、正文内容和角色私密设定一起复制出去。

什么时候动：自己看不出问题，准备去社区求助时。

⚠️

一键重置当前聊天数据不可撤回。当前世界还有价值时，先去“数据备份”导出，再碰它。

最后只记这个

看到问题，按这个方向找就够了。

看着不舒服→ 常用

正文信息太多 / 太少→ 正文注入

接口或模型有问题→ 连接与模型
